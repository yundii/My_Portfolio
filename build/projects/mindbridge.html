MindBridge.

A student wellbeing platform that connects supportive conversations with a traceable safety workflow.

Java 17Spring BootSpring AISpring SecurityReactor SSEH2 / MySQLApache POI

From a conversation to a reliable workflow

I built MindBridge to explore how agent-based applications can separate everyday conversation from consultation and safety concerns. The V2 prototype combines an English student interface with an administrator workspace for knowledge cards, screening reports, Excel records, and local alerts.

01 / ORCHESTRATION

Bounded agent routing

A runtime capped at eight stages routes messages through memory and supervision. Ordinary chat skips retrieval and reports; consultation and safety routes add knowledge retrieval and rule-based screening.

02 / ACCESS

Student and administrator spaces

Session login, CSRF protection, and server-side ownership checks isolate students’ conversations. Administrators maintain knowledge cards and review screening reports and alerts.

03 / MODEL INTEGRATION

Streaming with local and cloud adapters

Spring AI adapters support Ollama or OpenAI. A key-free template mode makes the app easy to demonstrate. BM25 retrieval supplies references, and Reactor streams replies through SSE.

04 / RELIABILITY

A durable safety workflow

High-risk records persist before a reply begins. After the response ends, an Excel write must succeed before a local notification is recorded. Jobs include retries, deduplication, restart recovery, and an audit trail.

The business flow

Student → Memory → Supervisor

CHAT → Companion → Streamed reply

CONSULT / RISK → Knowledge → Risk guardian → Counselor → Streamed reply

RISK workflow → Saved report → Excel success → Local notification record

Built to be verified

Seventeen automated tests cover authentication, cross-student access, routing, report suppression for ordinary chat, streaming persistence, model failures, cancellation, tool ordering, retries, restart recovery, and Excel string-cell safety. The student and administrator flows were also exercised in the browser.

Prototype scope

This is an engineering demonstration using synthetic data, not a clinical service. Screening uses transparent rules; alerts stay local and do not contact a counselor. MySQL configuration is included, while the tested local setup uses H2. LoRA fine-tuning, ChromaDB hybrid retrieval, MCP adapters, and external notification delivery are planned work. No clinical-accuracy or performance-improvement percentages are claimed.
